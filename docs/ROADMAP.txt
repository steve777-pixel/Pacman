---------------------------------------------------------------------
 PART A - COMMANDS TO RUN AFTER EDITING FILES
---------------------------------------------------------------------

Run all commands from the project root (the folder with CMakeLists.txt).
Your VCPKG_ROOT variable must be set (check with: echo $VCPKG_ROOT).

A1. THE NORMAL LOOP (use this 95% of the time)
    After editing any .h or .cpp file:

        cmake --build build
        ctest --test-dir build --output-on-failure

    - Because CMakeLists.txt uses file(GLOB_RECURSE ... CONFIGURE_DEPENDS),
      new .cpp files under src/ are picked up automatically on the next
      "cmake --build build". No manual re-configure is needed.
    - Run the game afterwards when the stage says so:

        ./build/pacman

A2. WHEN YOU ADD A NEW TEST FILE
    1. Create tests/test_xxx.cpp
    2. Add its name to the add_executable(pacman_tests ...) list in
       tests/CMakeLists.txt
    3. Re-configure and build:

        cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE=$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake
        cmake --build build
        ctest --test-dir build --output-on-failure

A3. WHEN YOU EDIT ANY CMakeLists.txt OR vcpkg.json
    Re-configure, then build and test (same three commands as A2).

A4. RUN ONLY SOME TESTS (while debugging one class)

        ctest --test-dir build -R Maze --output-on-failure
        ./build/tests/pacman_tests --gtest_filter=Maze.*
        ./build/tests/pacman_tests --gtest_filter=GhostAI.Pinky*
        ./build/tests/pacman_tests --gtest_list_tests

    -R takes a regex matched against the test name. --gtest_filter
    takes Suite.TestName patterns with * wildcards.

A5. SEE MORE DETAIL
        ctest --test-dir build --verbose
        cmake --build build --verbose

A6. WHEN THE BUILD BEHAVES STRANGELY (stale cache, weird linker errors)
    Clean rebuild (keeps the vcpkg package cache, so it is fast):

        rm -rf build
        cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE=$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake
        cmake --build build
        ctest --test-dir build --output-on-failure

A7. BUILD TYPES
    Debug (default for development, needed for the VS Code debugger):

        cmake -B build -S . -DCMAKE_BUILD_TYPE=Debug -DCMAKE_TOOLCHAIN_FILE=$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake

    Release (for final play-testing and speed):

        cmake -B build-release -S . -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake
        cmake --build build-release

A8. UPDATE vcpkg BASELINE (only when you deliberately want newer packages)

        git -C $VCPKG_ROOT pull
        vcpkg x-update-baseline

A9. GIT HABIT (end of every stage)

        git add -A
        git commit -m "Stage N: short description"

A10. GOLDEN RULE
    A stage is only finished when:
      - cmake --build build        finishes with no errors and no warnings
      - ctest --test-dir build     shows 100% tests passed


---------------------------------------------------------------------
 PART B - GLOBAL DESIGN RULES (apply to every stage)
---------------------------------------------------------------------

R1. SEPARATE LOGIC FROM DRAWING.
    Files in core/, world/, entities/, systems/ must NOT include any
    <SFML/...> header. Use your own Vec2i, Vec2f and Direction.
    Only graphics/, audio/, states/ and ui/ may use SFML.
    (This is what makes unit testing possible.)

R2. HEADERS.
    Every header starts with #pragma once. Include with the folder
    name:  #include "core/Types.h".  Prefer forward declarations in
    headers and put #include lines in the .cpp when possible.

R3. CONSTANTS.
    No magic numbers in code. Every speed, size, score, and timer
    lives in core/Constants.h as constexpr.

R4. OWNERSHIP.
    Use std::unique_ptr for owned polymorphic objects (ghosts,
    states). Use references for "I use this but do not own it".
    Never use raw new/delete. Never use global mutable variables.

R5. CONST-CORRECTNESS.
    Every method that does not change the object is marked const.
    Pass big objects by const reference.

R6. DETERMINISM.
    Game logic takes "float dt" as a parameter and never reads the
    clock directly. Tests then use fixed dt (e.g. 1.0f / 60.0f) and
    get the same result every run.

R7. TEST NAMES.
    TEST(SuiteName, BehaviorBeingChecked), for example:
    TEST(Maze, WallBlocksMovement). One behavior per test.

R8. ONE STAGE = ONE GIT COMMIT (at least).

=====================================================================
 STAGE 3 - ENTITY BASE CLASS AND PAC-MAN LOGIC
=====================================================================
Goal: Pac-Man moves correctly through the maze (logic only).

Files to write:
  include/entities/Entity.h   src/entities/Entity.cpp
  include/entities/Pacman.h   src/entities/Pacman.cpp
  tests/test_pacman.cpp

Requirements:
  Entity (abstract-ish base)
   - Protected members: Vec2f position (pixel-space logical position),
     Direction direction, float speed
   - Public: position(), tile() (position -> Vec2i), direction(),
     setDirection(), speed(), setSpeed()
   - virtual void update(float dt, const Maze& maze) = 0;
   - virtual destructor
   - Helper: isAtTileCenter() const (within a small epsilon)
  Pacman : public Entity
   - Methods: requestDirection(Direction)   (stores the "wanted" turn)
   - update(): moves along current direction by speed*dt; when at a
     tile center:
       1) if the buffered direction is walkable -> take it
       2) else if the current direction is blocked -> stop
   - Turn buffering: a turn requested slightly BEFORE the junction
     must still work when the tile center is reached
   - Instant reverse is allowed anywhere (Pac-Man can always reverse)
   - Tunnel: leaving one side of the tunnel row appears on the other
   - Movement never skips over a tile center (clamp with large dt)
   - reset(spawn) puts Pac-Man back at spawn with Direction::Left

OOP properties practiced:
   - Inheritance (Entity -> Pacman)
   - Abstraction (pure virtual update)
   - Polymorphism (virtual update, virtual destructor)
   - Encapsulation (protected state, public accessors)
   - Liskov substitution: anything that works on Entity& works on Pacman

Tests (test_pacman.cpp) - use a tiny hand-made Maze:
   - Moves right by speed*dt in an open corridor
   - Stops when the next tile is a wall
   - Does not enter a wall when a turn into a wall is requested
   - Buffered turn happens at the next junction
   - Reverse direction works immediately
   - Wraps through the tunnel
   - Large dt does not teleport through a wall
   - reset() restores spawn position and direction

DONE WHEN:
  [ ] All Pacman tests pass
  [ ] Behavior is deterministic (same inputs -> same output every run)

=====================================================================
 STAGE 6 - GHOSTS: BASE CLASS, MODES, FOUR PERSONALITIES
=====================================================================
Goal: four ghosts that move and choose targets like the original.

Files to write:
  include/entities/Ghost.h    src/entities/Ghost.cpp
  include/entities/Blinky.h   src/entities/Blinky.cpp
  include/entities/Pinky.h    src/entities/Pinky.cpp
  include/entities/Inky.h     src/entities/Inky.cpp
  include/entities/Clyde.h    src/entities/Clyde.cpp
  include/systems/GhostAI.h   src/systems/GhostAI.cpp
  tests/test_ghost_ai.cpp

Requirements:
  Ghost : public Entity   (shared logic lives HERE only)
   - Members: GhostMode mode, Vec2i scatterCorner, Vec2i startTile
   - protected pure virtual: Vec2i chaseTarget(const GhostContext&) const
       where GhostContext is a small struct: Pacman tile, Pacman
       direction, Blinky tile (needed by Inky), maze reference
   - Target selection by mode:
       Scatter  -> scatterCorner
       Chase    -> chaseTarget(ctx)
       Frightened -> random valid direction at each junction
       Eaten    -> the ghost-house tile
   - Movement rule at every tile center:
       * look at the next tile in the current direction, collect the
         legal neighbor tiles (not walls)
       * a ghost may NOT reverse by itself
       * choose the neighbor whose center is closest (straight-line)
         to the target
       * ties are broken in the order Up, Left, Down, Right
   - On a mode switch (Scatter <-> Chase, or to Frightened) the ghost
     reverses direction once
   - Speed depends on mode (normal, frightened, eaten, tunnel)
   - setMode(), mode(), reset(), isFrightened(), isEaten()
  Blinky   chase target = Pac-Man's tile
  Pinky    chase target = 4 tiles ahead of Pac-Man
           (optional: reproduce the original bug when Pac-Man faces
            up: target is 4 up AND 4 left)
  Inky     chase target = take the tile 2 ahead of Pac-Man, draw a
           vector from Blinky to it, double that vector
  Clyde    chase target = Pac-Man's tile when farther than 8 tiles,
           otherwise his own scatter corner
  Scatter corners: Blinky top-right, Pinky top-left,
                   Inky bottom-right, Clyde bottom-left
  GhostAI (system, not an entity)
   - Owns the global mode timer: scatter/chase schedule from
     Constants.h; update(dt) tells when to switch
   - startFrightened(duration) pauses the schedule timer and sets
     Frightened; when it ends, ghosts return to the schedule's mode
   - Owns NO targeting math (that is in the ghost subclasses)

OOP properties practiced:
   - Inheritance with a shared base class (no duplicated logic)
   - Polymorphism: std::vector<std::unique_ptr<Ghost>> and a single
     loop calling ghost->update(...); only chaseTarget differs
   - Abstract class (Ghost cannot be instantiated)
   - Template Method pattern: Ghost::update() is the fixed algorithm;
     chaseTarget() is the customization point
   - Finite State Machine (GhostMode)
   - Strategy-like separation: GhostAI decides WHEN, subclasses decide
     WHERE

Tests (test_ghost_ai.cpp), using small mazes and fixed contexts:
   - Blinky targets Pac-Man's tile
   - Pinky targets 4 tiles ahead in each of the four directions
   - Inky: for a known Blinky and Pac-Man position, target equals the
     hand-calculated doubled vector
   - Clyde: far (>8 tiles) targets Pac-Man; near targets his corner
   - Ghost never reverses on its own in a corridor
   - Mode switch makes the ghost reverse exactly once
   - Tie-break order Up, Left, Down, Right is respected
   - Scatter/chase schedule: after 7 s -> Chase, after 27 s -> Scatter
   - Frightened pauses the schedule timer and then resumes it
   - Eaten ghost heads for the house and returns to normal mode there

DONE WHEN:
  [ ] All ghost tests pass
  [ ] Ghosts visibly chase differently when drawn as colored circles
  [ ] Adding a fifth ghost would require only one new small subclass
